La Oficina 🏢

Tu squad de IA en una oficina 3D. Escribes aquí en vez de la terminal: cada agente es una sesión real de Claude Code con su rol, su memoria y sus tareas en paralelo.

$0 de API — usa tu suscripción Sesión propia por agente Tareas en paralelo

Requisitos previos

Para usar la app (obligatorio)

1. macOS con Apple Silicon. Windows está en el roadmap.

2. Claude Code instalado y con sesión iniciada. La regla simple: si claude arranca en tu terminal, La Oficina funciona. Requiere un plan Pro o Max (la cuenta gratuita de la web no habilita el CLI).

# Instalar (si no lo tienes)
curl -fsSL https://claude.ai/install.sh | bash
claude   # y sigue el flujo de /login con tu cuenta

3. Sin ANTHROPIC_API_KEY en el entorno. Si existe, Claude Code cobra por token en vez de usar tu plan. La app la quita del entorno de sus agentes, pero revisa tu ~/.zshrc por si acaso.

Para que los agentes usen herramientas (recomendado)

Homebrew en el PATH del shell. Los agentes ejecutan comandos con tu perfil de zsh; para que encuentren gh, node y demás, asegúrate de tener en ~/.zprofile:

eval "$(/opt/homebrew/bin/brew shellenv)"

La app además suma /opt/homebrew/bin, /usr/local/bin y ~/.local/bin al PATH de cada agente por si el perfil no carga.

Para el Revisor PR y el Publicador

Ambos usan GitHub CLI autenticado con tu cuenta:

brew install gh
gh auth login    # GitHub.com → SSH (o HTTPS) → Login with a web browser
gh auth status   # verifica: debe mostrar tu cuenta con scope 'repo'

El token queda en el keyring del sistema, así que sirve para los procesos que lanza la app sin re-loguearse. Además:

· git configurado (git config --global user.name / user.email) y con acceso a los repos donde vayas a abrir PRs.

· El Publicador necesita permiso para crear repos públicos en tu cuenta (usa gh repo create y GitHub Pages) — siempre pide confirmación antes de publicar algo.

· Opcional para el Revisor PR: acli (Atlassian CLI) y los conectores MCP de Jira/Slack configurados en Claude Code, si tus skills de PR hacen tracking en esas herramientas.

Opcionales

Dos cuentas (💼 work / 🔒 private): crea los directorios ~/.claude-work y ~/.claude-private iniciando sesión una vez con cada cuenta usando CLAUDE_CONFIG_DIR. La app te muestra ambos perfiles y cada uno tiene su squad, sus proyectos, su historial y sus preferencias. Sin ellos, usa tu cuenta normal ("🧑 mi cuenta").

Desarrollo (compilar la app): Node.js ≥ 18 · npm install · npm run dev.

Primer arranque

La app abre con una intro cinemática 🎬: un vuelo sobre la ciudad hasta el edificio de La Oficina, las puertas se abren y entras. Se salta con el botón o Esc, y se apaga en Preferencias. Después, un tour guiado 🎓 te señala las partes de la pantalla (repetible desde Configuración).

Verás una oficina con un solo agente activo (el principal, con un nombre real sorteado). Activa más roles desde ⚙️ Configuración → 👥 Agentes — hasta 6 a la vez, de un catálogo de 7 (Dev, Research, UI/UX, QA, Revisor PR, Docs, Publicador) más los que crees tú.

La barra superior

  • 💼 work / proyecto ▾ — el contexto en un solo control: perfiles como pestañas, la lista de proyectos debajo y ➕ Agregar proyecto… para sumar carpetas fuera de la raíz del perfil (quedan con 📌).
  • Repo ▾ y ⎇ rama ▾ — dos selectores al lado del proyecto. El primero, en qué repo estás trabajando: aparece cuando el proyecto es una carpeta con varios repos dentro (la raíz del workspace, elegida así para que los agentes carguen el contexto compartido) y la elección se recuerda para ese proyecto. El segundo, la rama, y no solo la enseña: cambia de rama. Lista las locales con la más reciente arriba y trae un filtro cuando hay muchas (Enter salta a la rama si el filtro deja una sola).
  • Cambiar de rama es un checkout de verdad, así que: no se hace con agentes trabajando —les rompería el turno debajo— y nunca se fuerza: si tienes cambios que se perderían, git se niega y te lo dice con sus palabras, para que los guardes o los stashees tú. La rama se relee al volver a la ventana y al terminar cada turno, porque cambia también por fuera de la app: un checkout tuyo en la terminal, o del agente cuando le pides una rama desde el chat. Con HEAD suelta (checkout a un commit o a un tag) muestra el commit en ámbar, porque ahí no hay rama.
  • 📱 Dónde correr — aparece solo si la carpeta tiene un proyecto que se pueda correr. Lista dispositivos, emuladores o scripts.
  • Contexto compartido del workspace — si junto al repo hay una carpeta ai-context/ con su repo-map/registry.json, la app carga sola el CONTEXT.md de ese repo y lo pone en la persona del agente, en vez de confiar en que vaya a buscarlo. El repo se toma del selector de rama; si no está en el mapa, se usa el único del proyecto que sí lo esté (con dos candidatos no adivina: elígelo tú). Las reglas no se precargan —son cientos de miles de caracteres— así que el agente sigue teniendo que leer las que apliquen, y el texto que se le inyecta se lo recuerda.
  • 📈 Estadísticas — en ⚙️. Dos vistas con rango 7d / 30d / todo: Resumen (conversaciones, turnos, tokens, tiempo, días activos, racha actual y máxima, hora punta, modelo favorito, mapa de actividad de 18 semanas y reparto por tripulante) y Modelos (tokens por día apilados por modelo, y el reparto con entrada, salida y porcentaje). El modelo, la hora y el desglose entrada/salida se guardan desde la v1.20: en días anteriores aparecen en «—», y no se rellenaron hacia atrás porque el historial guarda una sola fecha por conversación y repartir sus tokens por días habría sido inventar el gráfico.
  • 📄 Documentos — reportes, dashboards y páginas que genera el squad.
  • 🕘 Historial — conversaciones guardadas, con buscador.
  • + Nueva — abre una pestaña nueva y deja la actual donde estaba (⌘K). Si la que tienes ya está vacía, no abre otra.
  • ⚙️ Configuración — preferencias y acceso a Agentes (⌘,).

Un proyecto por conversación 🗂

  • Cada pestaña lleva su proyecto pegado, como cada ventana de terminal lleva su carpeta. Al volver a una pestaña, la barra vuelve sola a su proyecto, con el modelo, el permiso y el esfuerzo que tenías ahí.
  • Cambiar de proyecto no pisa la conversación: si el hilo tiene mensajes, el proyecto nuevo abre una pestaña nueva y el anterior se queda intacto. Así puedes pedir desarrollo en un clon y publicar desde otro, a la vez.
  • Se puede cambiar de proyecto con gente trabajando. Cada agente arrancó en su carpeta y sigue ahí. Lo que no se puede es cambiar de cuenta mientras trabajan: eso cambia la configuración, el squad y el escritorio completo.
  • En el selector: los proyectos que viven dentro de una carpeta raíz se ven anidados bajo ella —y eso importa, porque heredan su CLAUDE.md—; la flecha pliega cada raíz, y la ✕ quita un proyecto de la lista sin borrar la carpeta. Con ➕ Agregar proyecto puedes añadir cualquier carpeta: si no es un repo, se expanden también los proyectos de dentro.

Las etiquetas de arriba filtran por tipo. El botón sigue ahí al terminar, para revisar después qué se tocó, y cada conversación guarda el suyo. Volver a pulsarlo cierra el panel.
  • 🪙 Tokens: cada respuesta muestra cuántos tokens consumió (desglose en el tooltip) y el monitor lleva el acumulado de la conversación.
  • 🔀 Ver cambios: si la tarea editó archivos, la respuesta ofrece el git diff del proyecto coloreado, con los archivos nuevos aparte.
  • 🔍 Buscar (⌘F): barrita sobre el chat con n/total y navegación entre coincidencias. Y un click en el nombre de un mensaje filtra el chat a solo ese agente.

  • 🔘 Respuesta rápida: si la respuesta termina en un menú de opciones, salen como botones.
  • 🖼📁 Adjuntos: el botón 📎 del composer abre el selector, y también puedes pegar (⌘V) o arrastrar imágenes, archivos y carpetas al chat (las carpetas, arrastrándolas).
  • 💬 Citar: selecciona un fragmento de una respuesta y el botón flotante lo lleva al composer como cita, para preguntar sobre eso.
  • 🔁 Reintento automático: si una tarea falla por algo pasajero (límite de la API, timeout, red), se reintenta sola una vez a los 5s.
  • ⚠️ Aviso de colisión: si mandas una tarea de edición a un repo donde otro agente ya está editando, la app te advierte (no bloquea).
  • 📋 Copiar: cada bloque de código tiene botón de copiar al hover (y resaltado de sintaxis), y cada respuesta el suyo en la esquina.

Repartir el trabajo 👥

Si un encargo tiene partes independientes puedes pedir que se reparta entre compañeros, y cada uno trabaja con su propio contexto. Es la forma de partir un encargo grande sin llenar el del que lo recibió.

  • Hay que pedirlo, con /repartir … o diciéndolo («reparte esto entre el equipo»). Si no lo pides, quien recibe el encargo lo hace entero, aunque lleve dentro una lista de tareas: una lista describe el trabajo, no pide que se divida. Si él cree que conviene repartirlo, lo dice en una frase y decides tú.
  • Cada compañero toma un puesto y abre su pestaña, titulada con lo que se le encargó. Ves quién hace qué en vivo, y al terminar su conversación queda guardada.
  • Los personajes salen de tu equipo: primero quien esté sin hacer nada y, si no llegan, miembros inactivos que entran para esto y se van al acabar. Toman prestada la silla, no el rol: el compañero no hereda su personalidad ni su sesión.
  • Máximo cinco a la vez. La oficina tiene seis sillas y quien reparte ya ocupa una, y cada compañero es trabajo real corriendo en tu Mac. Pestañas no hay tope: si alguien se queda sin silla, su trabajo se ve igual y toma la primera que se libere.
  • El que reparte se queda esperando —no responde mientras los demás trabajan— y cierra con el resumen del conjunto. El detalle de cada uno lo tienes en su pestaña.
  • En el historial, esas conversaciones cuelgan de la que las repartió. Si borras la principal, se van con ella.

Al terminar, la respuesta de quien repartió dice cuánto contexto ocuparon sus compañeros — «👥 240k fuera de este hilo». Sin repartir, todo eso habría tenido que caber en esta conversación, y es lo que te dice si valió la pena.

Cuando terminan te avisa, con el nombre de cada personaje. Si acaban varios casi a la vez los junta en un solo aviso —cinco notificaciones seguidas se ignoran las cinco— y al cerrar el turno avisa otra vez: así distingues «ya puedes leer una parte» de «ya está todo».

Correr la app 📱

Con un proyecto Flutter o npm en la carpeta activa aparece 📱 en la barra. Desde ahí se lanza sin salir de La Oficina, y mientras corre queda una barra flotante sobre la escena.

Flutter

  • Dispositivos y emuladores — los móviles enchufados van primero, luego los emuladores arrancados y después escritorio y web: el orden es la recomendación. La lista se mantiene sola al enchufar y desenchufar, sin refrescar.
  • Solo lo que el proyecto soporta — una app sin carpeta web/ no ofrece Chrome, y una solo Android no ofrece el iPhone. El panel dice en qué plataformas corre el proyecto.
  • Lanzar o cerrar emuladores — el que ya está arriba muestra Cerrar en vez de Lanzar. Al lanzar se espera a que arranque de verdad antes de avisar.
  • Tus configuraciones — si el proyecto tiene .vscode/launch.json, salen las mismas que ofrece el editor, con su flavor y sus dart-defines.
  • Varios a la vez — un chip por dispositivo. Las acciones van a todos, que es el sentido de correr en iPhone y Android al tiempo; un clic en un chip enfoca solo ese. Dos de la misma plataforma no se puede: comparten el directorio de compilación.

En la barra: ⚡ hot reload, ↻ hot restart, ⏹ detener (o cancelar la compilación, si todavía va en eso), 🔗 abrir y ▤ la salida, que es donde aparece el motivo cuando una compilación falla.

Con ⚡ auto encendido se recarga al terminar cada turno del agente. Y no siempre con lo mismo: si tocó pubspec.yaml o código nativo avisa de que hay que recompilar, y si cambió main(), un enum, una jerarquía de clase o una variable de nivel de archivo —el caso típico de un provider— hace hot restart, porque un reload no vuelve a ejecutar los inicializadores globales y verías la app sin tu cambio.

Web y escritorio (npm)

Aquí el objetivo no es un dispositivo: es un script del package.json. Los que arrancan algo y se quedan corriendo van primero; los que compilan y terminan, abajo. El gestor lo decide el lockfile. No hay hot reload que pedir —el servidor de desarrollo recarga solo al guardar— así que queda arrancar, detener, ver la salida y abrir la URL, que se detecta de lo que imprime el servidor.

Configuración ⚙️

  • 👥 Agentes — el submenu del squad: activa/desactiva con el switch (hasta 6; el 1º activo es el principal), reordena arrastrando el grip ⠿, renombra, elige personaje en la galería 3D (46 modelos, sin repetir — el cambio aplica al instante), edita su ✏️ Personalidad (un .md por personaje) y fija su 🧠 modelo propio (UI/UX con Opus, QA con Haiku… los demás usan el global) y su 🎚 esfuerzo propio (un QA que solo corre tests no necesita el mismo que quien implementa). Arriba hay presets (Equipo web, mobile, research o solo el principal) que activan un conjunto de roles de un clic respetando tus nombres. Los roles personalizados se crean y editan ahí mismo, y ♻️ Restaurar predeterminados recupera los borrados.
  • 🧩 Skills — superpoderes del perfil: catálogo curado del repo oficial de Anthropic (frontend design para el UI/UX, testing con navegador para QA, Word/PDF/PowerPoint/Excel para Docs…), instalar desde cualquier repo de GitHub (detecta las skills adentro), crear las tuyas con el esqueleto listo, y la sección Plugins: paquetes completos (skills + comandos + agentes + MCP) instalables desde marketplaces o repos directos. Todo llega a tus agentes automáticamente.
  • 🌐 Servidores MCP — herramientas externas para los agentes: Playwright (manejan un navegador real — QA de interfaces vivas), Chrome DevTools, Context7 (docs al día), Figma, o cualquier servidor propio (comando npx o URL).
  • Modelo — el global: Opus 5 · 1M (recomendado), Fable 5, Sonnet 5 y Haiku 4.5, más la generación anterior (Opus 4.8, 4.7, 4.6 y Sonnet 4.6). Se recuerda por perfil. Ojo: los 4.x tienen una ventana de 200k, así que el % de contexto sube mucho más rápido que con un modelo de 1M.
  • Esfuerzo — cuánto razona antes de responder, de bajo a máximo. Más esfuerzo son mejores respuestas y más lentas. Por defecto usa el del CLI, así que si no lo tocas nada cambia. Se recuerda por proyecto, como el permiso: un repo que solo consultas no necesita el mismo que uno donde implementas.
  • Permiso — el mismo ✏️/🔒 del chip del composer. Se recuerda por proyecto: un repo de cliente puede quedarse en solo lectura mientras el propio sigue en edición.
  • 🎬 Intro — al abrir la app, una secuencia corta llega al edificio y entra por la puerta; se salta con el botón o Esc, y se desactiva en Preferencias (también se omite si el sistema pide menos movimiento).
  • Tema — Clásico, Noche 🌙, Playa, y las estaciones con partículas cayendo: 🌸 Sakura (pétalos de cerezo), 🍂 Otoño (hojas secas) y ❄️ Invierno (nieve). O 🌗 Auto: Noche de 19:00 a 07:00, Clásico de día.
  • Documentos — la carpeta donde el squad guarda lo que genera.
  • 🧠 Pizarra SQUAD.md — memoria común del squad en la raíz del proyecto: los agentes la leen y anotan avances para el resto.
  • Sonido y Notificaciones — por separado: el «ding» dentro de la app y los avisos de macOS. Los avisos salen también con la ventana delante, porque un turno largo se pierde igual si estás mirando otra pestaña.
  • 🖥 Abrir terminal en el proyecto — Warp (o la predeterminada) en la carpeta del proyecto actual, para lo interactivo que la app no cubre (plan mode, /login, git fino…).
  • 📘 CLAUDE.md del proyecto — abre (o crea) las instrucciones que TODOS los agentes leen al trabajar en ese repo, sin salir de la app.
  • 📈 Estadísticas — tareas, tokens y tiempos por agente, con las barras de los últimos 7 días.
  • 🔧 Diagnóstico — los últimos eventos de cada agente y los errores con su detalle, para copiar o exportar.
  • 🎬 Intro y 🎓 Tour — activar la intro de arranque y relanzar el tour guiado.
  • Calidad — 🎬 Cine (todos los efectos), ✨ Normal o 🔋 Ligera (ahorra batería).
  • Mascota 🦊 — zorro, shiba, husky, lobo, venado o alpaca: pasea por la oficina, husmea, come y cuando hay standup se acerca a mirar la reunión. Se elige (o se quita) en Preferencias.
  • Standup programado — a la hora que elijas en días hábiles; al terminar puedes 📤 compartir el resumen a Slack (canal configurable).
  • 💾 Exportar / 📥 Importar configuración — squad, personalidades, plantillas y proyectos en un JSON, para respaldar o migrar de máquina. Además se guarda un respaldo automático semanal.
  • 🌗 Apariencia — tema claro u oscuro para la interfaz; Auto sigue al del sistema. Es aparte del tema de la escena 3D.
  • 🌐 Idioma — español o inglés. Cambia toda la interfaz y esta guía, y los agentes responden en el idioma elegido.
💡 La Oficina vs la terminal: usa la app para el flujo del día (tareas, investigación, standup, trabajo en paralelo) y el botón 🖥 para la cirugía fina interactiva.

Documentos 📄

Pide un reporte, documento, dashboard o página y el agente genera un HTML autocontenido (con imágenes) que se abre dentro de la app. En el panel 📄: abrir, revelar en Finder, exportar como .zip, 🗑 borrar (va a la papelera, se puede recuperar) y 💬 usar como contexto del próximo mensaje («revisa este reporte y actualízalo»). Y si quieres publicarlo en la web, el Publicador lo sube a GitHub Pages — siempre con tu confirmación, porque queda público.

Historial 🕘

Cada conversación se guarda sola (se conservan las 100 más recientes). Hay buscador por título, proyecto y por el texto de los mensajes (muestra un extracto), ✏️ renombrar, 📌 fijar (las fijadas van arriba y no se purgan nunca) y ⬇ exportar a Markdown con metadatos y todos los mensajes. Al abrir una, el squad recuerda todo el contexto (se retoman las sesiones reales de Claude). 🗑 la borra.

Monitores 📊

Arriba a la izquierda, en columna: Sistema (CPU y RAM reales del Mac, memoria de la app) y Claude (modelo en uso, 🪙 tokens acumulados de la conversación el % de contexto que lleva ocupado la conversación —cuando se llena, Claude resume y el agente recuerda menos— y tu % de suscripción: sesión de 5h y semana con sus tiempos de reset). Si vas por encima del 90% de la sesión, la app te avisa al despachar una tarea. Y cuando una conversación llega al 85% de su contexto, sale un aviso para continuarla en un chat nuevo: le pide un resumen de traspaso a quien viene trabajando en el hilo y lo deja escrito en el composer sin enviarlo, para que lo leas antes. Puedes llevarlo a una pestaña nueva —así conservas el hilo viejo para consultarlo— o seguir aquí, que arranca de cero en la misma pestaña y te la deja con su nombre y su sitio. Conviene hacerlo antes de llegar al tope: al llenarse, Claude resume solo y se pierde el detalle, que es justo lo que cuesta rehacer en un hilo largo. Fuera de la ventana, el Dock muestra cuántos agentes trabajan (y el ícono salta al terminar en background) y la barra de menús 🏢 tiene lo mismo con menú rápido. Debajo de esas dos aparecen Trabajadores activos (quién trabaja ahora, con su cronómetro y un ⏹ para detenerlo) y Chats activos (tus pestañas); los dos se esconden cuando no hay nada que mostrar.

La vida de la oficina

Cuando nadie les pide nada: toman café, sueltan frases de su rol, escuchan música 🎧, pasean y se visitan. En cuanto llega trabajo, vuelven a su puesto. Al terminar una tarea, caminan a entregarla 🙌, y en el standup se reúnen de pie en el centro de la sala. El encuadre de la cámara se recuerda entre sesiones — doble click en la escena lo restablece. Si la ventana queda tapada o minimizada, la escena baja el ritmo para no gastar batería; visible (aunque sea en otra pantalla), corre a 60fps. Y mientras el squad trabaja, la app evita que el Mac se duerma para no matar tareas a medias.

Actualizaciones 🔄

La app se actualiza sola: comprueba al arrancar, descarga la versión nueva en segundo plano y te avisa cuando está lista. No se reinicia por su cuenta — se aplica cuando tú lo decidas, porque reiniciar a mitad de una tarea sería perderla. Si algo falla (sin red, o un release publicado a mano sin sus metadatos), se cae al aviso de siempre: te notifica y te descarga el instalador.

Además de al arrancar, comprueba cuando el Mac despierta y cuando vuelves a la ventana (como mucho una vez cada 15 minutos), y cada 2 horas si la dejas abierta. Si no quieres esperar, ⚙️ → Buscar actualizaciones pregunta al momento y te dice qué encontró: estás al día o la descarga en marcha. Todo lo que comprueba queda anotado en auto-update.log, dentro de la carpeta de datos de la app.

Si algo se ve raro

  • Si falta el binario claude, la app te lo dice al arrancar con las instrucciones de instalación.
  • La primera notificación de macOS puede pedir permiso (Ajustes → Notificaciones).
  • ¿Respuestas sin personalidad o personajes "pegados"? Puede haber una instancia vieja corriendo: cierra todas las ventanas de La Oficina y ábrela de nuevo (o pkill -f "la-oficina").
  • El primer mensaje de cada agente tarda unos segundos (arranque de Claude Code).
  • ¿El Revisor PR o el Publicador fallan con git o GitHub? → revisa gh auth status en tu terminal.
  • Cuando hay versión nueva en GitHub, la notificación la descarga directo a ~/Descargas y abre el instalador — solo arrastras a Aplicaciones.
  • Si el Mac se suspendió a media tarea (batería, tapa cerrada), al despertar la app te avisa: cancela con ⏹ y usa 🔁 Reintentar.
