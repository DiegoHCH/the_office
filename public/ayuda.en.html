La Oficina 🏢

Your AI squad in a 3D office. You type here instead of in the terminal: every agent is a real Claude Code session with its own role, memory and tasks running in parallel.

$0 in API — uses your subscription One session per agent Parallel tasks

Prerequisites

To use the app (required)

1. macOS with Apple Silicon. Windows is on the roadmap.

2. Claude Code installed and logged in. Simple rule: if claude starts in your terminal, La Oficina works. It needs a Pro or Max plan (the free web account does not enable the CLI).

# Install (if you don't have it)
curl -fsSL https://claude.ai/install.sh | bash
claude   # then follow the /login flow with your account

3. No ANTHROPIC_API_KEY in the environment. If it exists, Claude Code charges per token instead of using your plan. The app strips it from its agents' environment, but check your ~/.zshrc just in case.

So agents can use tools (recommended)

Homebrew on the shell PATH. Agents run commands with your zsh profile; so they can find gh, node and friends, make sure you have this in ~/.zprofile:

eval "$(/opt/homebrew/bin/brew shellenv)"

The app also adds /opt/homebrew/bin, /usr/local/bin and ~/.local/bin to every agent's PATH in case the profile does not load.

For the PR Reviewer and the Publisher

Both use the GitHub CLI authenticated with your account:

brew install gh
gh auth login    # GitHub.com → SSH (or HTTPS) → Login with a web browser
gh auth status   # check: it must show your account with the 'repo' scope

The token lives in the system keyring, so it works for the processes the app spawns without logging in again. Also:

· git configured (git config --global user.name / user.email) and with access to the repos where you will open PRs.

· The Publisher needs permission to create public repos in your account (it uses gh repo create and GitHub Pages) — it always asks for confirmation before publishing anything.

· Optional for the PR Reviewer: acli (Atlassian CLI) and the Jira/Slack MCP connectors configured in Claude Code, if your PR skills track work in those tools.

Optional

Two accounts (💼 work / 🔒 private): create the directories ~/.claude-work and ~/.claude-private by logging in once with each account using CLAUDE_CONFIG_DIR. The app shows both profiles and each one has its own squad, projects, history and preferences. Without them, it uses your normal account ("🧑 my account").

Development (building the app): Node.js ≥ 18 · npm install · npm run dev.

First launch

The app opens with a cinematic intro 🎬: a flight over the city up to the La Oficina building, the doors open and you walk in. Skip it with the button or Esc, and turn it off in Preferences. After that, a guided tour 🎓 points out the parts of the screen (repeatable from Settings).

You will see an office with a single active agent (the lead, with a randomly drawn real name). Enable more roles from ⚙️ Settings → 👥 Agents — up to 6 at a time, out of a catalog of 7 (Dev, Research, UI/UX, QA, PR Reviewer, Docs, Publisher) plus the ones you create.

The top bar

  • 💼 work / project ▾ — the whole context in one control: profiles as tabs, the project list below and ➕ Add project… to bring in folders outside the profile root (they show up with 📌).
  • Repo ▾ and ⎇ branch ▾ — two selectors next to the project. The first one, which repo you are working in: it shows up when the project is a folder with several repos inside (the workspace root, chosen that way so the agents load the shared context) and the choice is remembered for that project. The second one, the branch, and it does not just show it: it switches branch. It lists the local ones with the most recent on top, and brings a filter when there are many (Enter jumps to the branch if the filter leaves only one).
  • Switching branch is a real checkout, so: it is not done while agents are working —it would break their turn from under them— and it is never forced: if you have changes that would be lost, git refuses and tells you in its own words, so you commit or stash them yourself. The branch is read again when you come back to the window and when each turn ends, because it also changes outside the app: a checkout of yours in the terminal, or the agent’s when you ask it for a branch from the chat. With a detached HEAD (a checkout to a commit or a tag) it shows the commit in amber, because there is no branch there.
  • 📱 Where to run— only shows up if the folder holds a project that can be run. Lists devices, emulators or scripts.
  • 📄 Documents — reports, dashboards and pages the squad creates.
  • 🕘 History — saved conversations, with search.
  • + New— opens anew taband leaves the current one where it was (⌘K). If the one you're on is already empty, it doesn't open another.
  • ⚙️ Settings — preferences and access to Agents (⌘,).

One project per conversation 🗂

  • Each tab carries its own project, the way each terminal window carries its own folder. Come back to a tab and the bar returns to its project on its own, with the model, the permission and the effort you had there.
  • Switching project doesn't overwrite the conversation:if the thread has messages, the new project opens a new tab and the previous one stays untouched. That's how you can ask for development in one clone and publish from another, at the same time.
  • You can switch project while people are working.Each agent started in its own folder and stays there. What you can't change is theaccountwhile they work: that changes the settings, the squad and the whole desktop.
  • In the picker:projects that live inside a root folder show nested under it — and that matters, because they inherit itsCLAUDE.md—; the arrow collapses each root, and the ✕ removes a project from the list without deleting the folder. With➕ Add projectyou can add any folder: if it isn't a repo, the projects inside it are listed too.

Splitting the work 👥

If a job has independent parts you can ask for it to besplit among teammates, each working with its own context. That is how a big request gets broken up without filling the context of whoever received it.

  • You have to ask for it, with/repartir …or by saying so (“split this among the team”). If you don't ask, whoever gets the job does all of it,even if it contains a list of tasks: a list describes the work, it doesn't ask for it to be divided. If they think splitting it is worth it, they say so in one sentence and you decide.
  • Each teammate takes a desk and opens its own tab, titled with what it was asked to do. You see who is doing what live, and its conversation is saved when it finishes.
  • The characters come from your own squad:first whoever is idle and, if that is not enough, inactive members who step in for this and leave when it is over. They lend the chair, not the role: the teammate inherits neither their personality nor their session.
  • Five at a time, max.The office has six chairs and whoever splits the work already takes one, and each teammate is real work running on your Mac. There is no cap on tabs: if someone is left without a chair, their work is still visible and they take the first one that frees up.
  • Whoever splits the work waits— it does not answer while the others work — and closes with the overall summary. The detail of each one is in its own tab.
  • In thehistory, those conversations hang under the one that split the work. Delete the main one and they go with it.

When it is done, the answer from whoever split the work says how much context the teammates used —“👥 240k outside this thread”. Without splitting, all of it would have had to fit in this conversation — that is what tells you whether it was worth it.

You get a notification as each one finishes, with its character’s name. If several finish at nearly the same time they are grouped into one — five notifications in a row and all five get ignored — and there is another when the turn closes: that way you can tell “one part is ready to read” from “everything is done”.

Running the app 📱

With aFlutter or npmproject in the active folder, 📱 appears in the top bar. You launch from there without leaving La Oficina, and while it runs a floating bar stays above the scene.

Flutter

  • Devices and emulators— plugged-in phones come first, then booted emulators, then desktop and web: the order is the recommendation. The list keeps itself up to date as you plug and unplug, with no refreshing.
  • Only what the project supports— an app with noweb/folder does not offer Chrome, and an Android-only one does not offer the iPhone. The panel tells you which platforms the project runs on.
  • Launching and closing emulators— one that is already up showsCloseinstead ofLaunch. When launching, it waits until the emulator has really booted before saying so.
  • Your own configurations— if the project has a.vscode/launch.json, you get the same ones your editor offers, with their flavor and dart-defines.
  • Several at once— one chip per device. Actions go to all of them, which is the whole point of running on iPhone and Android at the same time; clicking a chip focuses just that one. Two of the same platform is not possible: they share the build directory.

In the bar:⚡ hot reload, ↻ hot restart, ⏹ stop(or cancel the build, if it is still on that),🔗 open and ▤ the output, which is where the reason shows up when a build fails.

With⚡ autoon, it reloads when each agent turn finishes. And not always the same way: if it touchedpubspec.yamlor native code it tells you a rebuild is needed, and if it changedmain(), an enum, a class hierarchy or a file-level variable —the typical case being a provider— it does ahot restart, because a reload does not re-run global initializers and you would be looking at the app without your change.

Web and desktop (npm)

Here the target is not a device: it is ascriptin thepackage.json. The ones that start something and keep running come first; the ones that build and exit go below. The package manager is decided by the lockfile. There is no hot reload to ask for —the dev server refreshes on save by itself— so what is left is start, stop, watch the output and open the URL, which is picked up from what the server prints.

Settings ⚙️

  • 👥 Agents — the squad submenu: enable/disable with the switch (up to 6; the first active one is the lead), reorder by dragging the ⠿ grip, rename, pick a character from the 3D gallery (46 models, no repeats — the change applies instantly), edit their ✏️ Personality (one .md per character) and pin their 🧠 own model(UI/UX on Opus, QA on Haiku… the rest use the global one) and its🎚 own effort(a QA that only runs tests does not need the same as whoever implements). At the top there arepresets (Web team, mobile, research or just the lead) that enable a set of roles in one click while keeping your names. Custom roles are created and edited right there, and ♻️ Restore defaults brings back the deleted ones.
  • 🧩 Skills — the profile's superpowers: a curated catalog from Anthropic's official repo (frontend design for UI/UX, browser testing for QA, Word/PDF/PowerPoint/Excel for Docs…), install from any GitHub repo (it detects the skills inside), create your own with the skeleton ready, and the Plugins section: full packages (skills + commands + agents + MCP) installable from marketplaces or direct repos. Everything reaches your agents automatically.
  • 🌐 MCP servers — external tools for the agents: Playwright (they drive a real browser — QA on live interfaces), Chrome DevTools, Context7 (up-to-date docs), Figma, or any server of your own (npx command or URL).
  • Model— the global one: Opus 5 · 1M (recommended), Fable 5, Sonnet 5 and Haiku 4.5, plus the previous generation (Opus 4.8, 4.7, 4.6 and Sonnet 4.6). Remembered per profile. Note: the 4.x models have a 200k window, so the% of contextclimbs far faster than with a 1M model.
  • Effort— how much it reasons before answering, fromlowtomax. More effort means better answers and slower ones. It defaults to the CLI’s, so nothing changes unless you touch it. It is rememberedper project, like the permission: a repo you only read does not need the same as one where you implement.
  • Permission — the same ✏️/🔒 as the composer chip. Remembered per project: a client repo can stay read-only while your own keeps editing.
  • 🎬 Intro — when the app opens, a short sequence reaches the building and walks in through the door; skip it with the button or Esc, and disable it in Preferences (it is also skipped if the system asks for reduced motion).
  • Theme — Classic, Night 🌙, Beach, and the seasons with falling particles: 🌸 Sakura (cherry petals), 🍂 Autumn (dry leaves) and ❄️ Winter (snow). Or 🌗 Auto: Night from 19:00 to 07:00, Classic during the day.
  • Documents — the folder where the squad saves what it creates.
  • 🧠 SQUAD.md board — the squad's shared memory at the project root: agents read it and note progress for the others.
  • Sound and Notifications— separately: the “ding” inside the app and the macOS notifications. Notifications fireeven with the window in front, because a long turn is missed just the same if you are looking at another tab.
  • 🖥 Open terminal in the project — Warp (or your default) in the current project folder, for the interactive things the app does not cover (plan mode, /login, fine-grained git…).
  • 📘 Project's CLAUDE.md — opens (or creates) the instructions EVERY agent reads when working in that repo, without leaving the app.
  • 📈 Statistics — tasks, tokens and times per agent, with bars for the last 7 days.
  • 🔧 Diagnostics — the latest events from each agent and errors with their detail, ready to copy or export.
  • 🎬 Intro and 🎓 Tour — turn the startup intro on and relaunch the guided tour.
  • Quality — 🎬 Cinematic (all effects), ✨ Normal or 🔋 Light (saves battery).
  • Pet 🦊 — fox, shiba, husky, wolf, deer or alpaca: it wanders the office, sniffs around, eats and comes over to watch the standup. Pick one (or none) in Preferences.
  • Scheduled standup — at the time you pick, on weekdays; when it ends you can 📤 share the summary to Slack (configurable channel).
  • 💾 Export / 📥 Import settings — squad, personalities, templates and projects in a JSON, to back up or move machine. There is also a weekly automatic backup.
  • 🌗 Appearance — light or dark theme for the interface; Auto follows the system. Separate from the 3D scene theme.
  • 🌐 Language — Spanish or English. It changes the whole interface and this guide, and the agents answer in the language you pick.
💡 La Oficina vs the terminal: use the app for the daily flow (tasks, research, standup, parallel work) and the 🖥 button for fine interactive surgery.

Documents 📄

Ask for a report, document, dashboard or page and the agent generates a self-contained HTML (with images) that opens inside the app. In the 📄 panel: open, reveal in Finder, export as .zip, 🗑 delete (it goes to the trash, so it can be recovered) and 💬 use as context for the next message ("review this report and update it"). And if you want it on the web, the Publisher pushes it to GitHub Pages — always with your confirmation, because it becomes public.

History 🕘

Every conversation saves itself (the 100 most recent are kept). There is search by title, project and by message text (it shows an excerpt), ✏️ rename, 📌 pin (pinned ones go on top and are never purged) and ⬇ export to Markdown with metadata and every message. When you open one, the squad remembers all the context (the real Claude sessions are resumed). 🗑 deletes it.

Monitors 📊

Top left, stacked in a column:System (your Mac's real CPU and RAM, app memory) and Claude (model in use, 🪙 accumulated conversation tokens the % of contextthe conversation is using — when it fills up, Claude summarises and the agent remembers less — and your subscription %: the 5h session and the week with their reset times). Above 90% of the session, the app warns you when dispatching a task. And when a conversation reaches85% of its context, a notice offers tocontinue it in a new chat: it asks whoever has been working on the thread for a handoff summary and leaves it written in the composer without sending it, so you can read it first. You can take it to anew tab— that way you keep the old thread to refer back to — orstay here, which starts fresh in the same tab and keeps its name and position. Best donebeforeyou hit the ceiling: once full, Claude summarises on its own and the detail is lost — exactly what is expensive to rebuild in a long thread. Outside the window, theDock shows how many agents are working (and the icon bounces when something finishes in the background) and the menu bar 🏢has the same with a quick menu. Below those two you getActive workers(who is working right now, with their timer and a ⏹ to stop them) andActive chats(your tabs); both hide when there is nothing to show.

Office life

When nobody needs them: they grab coffee, drop lines about their role, listen to music 🎧, wander and visit each other. As soon as work arrives, they go back to their desk. When a task finishes they walk over to hand it off 🙌, and during the standup they gather standing in the middle of the room. The camera framing is remembered between sessions — double-click the scene to reset it. If the window is covered or minimized, the scene slows down to save battery; visible (even on another screen), it runs at 60fps. And while the squad works, the app keeps the Mac from sleeping so tasks are not killed halfway.

Updates 🔄

The app updates itself: it checks on startup, downloads the new version in the background and tells you when it is ready.It does not restart on its own— it is applied when you decide, because restarting mid-task would lose it. If anything fails (no network, or a release published by hand without its metadata), it falls back to the old notice: it tells you and downloads the installer.

Beyond startup, it checks when the Mac wakes up and when you come back to the window (at most once every 15 minutes), and every 2 hours if you leave it open. If you would rather not wait, ⚙️ → Check for updates asks right away and tells you what it found: you are up to date or the download under way. Everything it checks is written down in auto-update.log, inside the app data folder.

If something looks off

  • If the claude binary is missing, the app tells you at startup with the install instructions.
  • The first macOS notification may ask for permission (Settings → Notifications).
  • Responses with no personality, or characters "stuck"? There may be an old instance running: close every La Oficina window and open it again (or pkill -f "la-oficina").
  • Each agent's first message takes a few seconds (Claude Code startup).
  • PR Reviewer or Publisher failing on git or GitHub? → check gh auth status in your terminal.
  • When there is a new version on GitHub, the notification downloads it straight to ~/Downloads and opens the installer — you just drag it to Applications.
  • If the Mac slept mid-task (battery, lid closed), the app warns you on wake: cancel with ⏹ and use 🔁 Retry.
